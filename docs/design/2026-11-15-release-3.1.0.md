# Krusty 3.1.0 release

Date: 2026-11-15. Status: proposed.

## Scope and increment

Release the additive PQB WASM interface merged in #250 (`7071c0f4`), the only
change since `v3.0.0`. The Unreleased notes are Added, so this is a minor release.
The Rust public signatures and deterministic keys/scripts remain unchanged.
Native vaults now reuse immutable public material across operations. The cache
contains no secret witnesses and has no exposure/journal state.

The npm package gains opaque vault/request handles for root BIP39/BIP85
wallet derivation and 24-word child restoration, exact public scripts/commitments/
menu points, transaction-bound selected disclosure, co-signing and strict deposit
PSBT signing. The existing QSB-HORS-v1 and Nostr metadata response remain intact.
See [the integration contract](../pqb-wasm.md) for exact types and a Bramble example.

The caller must durably journal the exact digest before authorization and
permanently reject a different digest for that vault. Funding, recipients, fees,
puzzle verification and Bitcoin consensus remain the caller's responsibility.
Returned JS disclosure copies cannot reliably be wiped. Compatibility checks
cover public Python/TypeScript vectors and the built WASM package, not a real
puzzle solve, on-chain spend or end-to-end Bramble integration.

## Internal dependency ranges

Keep internal `krusty-kms-*` path requirements at `3.0.0`: `^3.0.0` already covers
3.1.0. No dependent crate uses a newly added native public API or needs a new
cross-crate security invariant. The native public-material cache is a performance
change; it does not alter the existing contract. The new WASM validation is local
to the boundary crate. Refresh the workspace and both standalone memory-probe
lockfiles to the new workspace version without updating external dependencies.

## Verification and publication

Verify the dated changelog, package all eight publishable crates, and run
`tools/check.sh all`, including the built-package JavaScript/TypeScript consumer
checks. Independently review the entire release diff before opening the PR.

This PR only prepares 3.1.0. Merging it starts the protected npm workflow for
`@starknetfoundation/krusty-kms-wasm@3.1.0`; approval is still required. A maintainer
may separately authorize tagging the merged main commit `v3.1.0`, which starts
the protected crates.io OIDC workflow. Do not publish locally, reuse 3.0.0, tag a
release branch or move an existing tag. Bramble can pin 3.1.0 only after npm
publication is verified. This preparation authorizes no merge, tag or publication.
