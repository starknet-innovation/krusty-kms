# Krusty 0.15.0 release

Date: 2026-11-04. Status: accepted.

Release the features and security fixes merged since 0.14.0. Use a pre-1.0
minor version because the increment adds public API and changes behaviour
that dependents on `^0.14.0` must opt into:

- new Bitcoin P2WPKH derivation, PSBT and BIP-322 signing APIs (#188) and
  `QSB-HORS-v1` vault secret primitives (#187), with WASM bindings;
- `EthSigner::public_key_calldata` replaces the deprecated
  `EthSigner::public_key_xy` and `felt_to_u256_pair`, which reduced
  secp256k1 coordinates modulo the Stark prime (#195);
- `encrypt_keystore` / WASM `encryptKeystore` reject `scrypt_n` above 2^18,
  and `decrypt_keystore` applies the 256 MiB scrypt ceiling and a 128-byte
  salt limit to native v1 keystores (#196);
- `NatsMultisigCoordinator` and the HTTP coordinator refuse envelopes above
  1 MiB on both send and receive (#196).

The C ABI `kms_encode_transfer_calls` JSON shape also changes (#195), but
`krusty-kms-cabi` is not published to crates.io; its wrappers pick it up from
source.

All workspace packages inherit 0.15.0. Internal `krusty-kms-*` path
dependency requirements move from 0.14.0 to 0.15.0 so packaged crates
resolve the same release family; pre-1.0 caret ranges on 0.14.0 exclude
0.15.0. Path dependencies without a version requirement stay unchanged.

The dated changelog entry is the former `## [Unreleased]` notes. Two notes
said "the next minor release" for the removal of the deprecated Eth helpers
and for the deferred RPC body cap (audit M-2). Written before this release,
they meant the minor after the one that ships them, so the entry now names
0.16.0 explicitly.

The same range carries the WASM secret-argument wiping (#190), the wiped
BIP-32 derivation and HMAC (#189), the `async-nats` 0.51.0 bump (#191), the
`KRUSTY_ORACLE_REQUIRE_CONFIRM` fail-closed parsing (unpublished oracle, #196)
and CI action bumps (#193, #194). No implementation or export changes occur
in this release-preparation PR.

Package all eight publishable crates before merging. Tag only the merged
`main` commit as `v0.15.0`, then use the protected crates.io GitHub Actions
OIDC workflow. The npm workflow publishes `@starknetfoundation/krusty-kms-wasm`
0.15.0 on merge to `main`, because the WASM package takes the workspace
version and already-published versions are skipped. Keep the release tag
immutable; retry the same workflow for partial publication, or use a new
patch version for source fixes.
