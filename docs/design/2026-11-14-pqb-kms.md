# PQB KMS primitives

Support the fixed `PQB` real-puzzle profile from fireblocks-labs/pqb at
`eccdd09772edf14ab37fc63992b0626ad7ff2221`, separately from QSB-HORS-v1.
No release version bump or FFI/WASM exports are included.

A redacted, non-serializable vault owns a wiped 32-byte seed. Constructors accept
an imported seed, BIP85 child entropy, or a BIP39 wallet and hardened child index.
BIP85 child entropy and the bound seed never leave the wallet constructor.
Public material includes the exact locking script, HORS commitments, compressed
co-signing and deposit public keys, and menu recovery points (never menu scalars).
The fixed script is generated from these commitments with no user-supplied opcodes.

Disclosure requests validate canonical unsigned transaction serialization, input
index, output amounts, duplicate/null outpoints, and disjoint 8/9 HORS selections
and bounded menu choices. They bind the full transaction, lock hash, input index,
and ordered selection to a domain-separated journal digest. Authorization checks
the request belongs to this vault before releasing only the selected witnesses
and an ordinary RFC6979 low-S DER SIGHASH_ALL signature over the entire lock.
No generic digest-signing or arbitrary-label secret derivation API is exported.

These are stateless KMS primitives, not a Bitcoin consensus verifier or a wallet.
The caller verifies funding/amounts, destinations/fees and grind results, and must
persist the request digest as exposed before authorization, refusing any different
request for that vault forever, including after restore. Reconstructing a vault
does not restore a journal. No claim of puzzle validation or end-to-end spending
is made. Deposit signing uses the existing strict P2WPKH PSBT validation.

Secret buffers, scalar arithmetic and SHA-2 state use existing wiped types.
Menu commitments use SHA-1 as specified by PQB. The RustCrypto sha1
and ripemd dependencies enable zeroize to wipe secret-bearing hash state;
Compile-time bounds pin that guarantee. Compiler-created temporaries and
register spills are outside the wiping guarantee. Disclosure buffers redact Debug and wipe on drop.

Verification uses committed public Python/TypeScript vectors, plus a reproducible
reference exporter for wallet derivation and selective witness material. Negative
tests cover invalid selections, transaction mutations, and cross-vault requests.
The reference vectors do not contain real puzzle solves. The implementation is
larger than the usual PR limit because derivation, secret menus, the fixed script,
and transaction-aware disclosure must agree byte for byte; modules stay small.
