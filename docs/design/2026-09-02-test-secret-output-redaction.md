# Test-output redaction for derivation vectors

Date: 2026-09-02. Status: accepted. Origin: CodeQL cleartext-logging alerts.

## Problem

Several derivation tests printed a fixed mnemonic and the resulting private
keys for manual comparison with TypeScript output. Although these are test
vectors rather than user credentials, test logs are routinely retained and
shared; treating derived private material as ordinary diagnostics weakens the
SDK's secret-handling boundary and trains downstream users to do the same.

## Decision

- Tests must not print mnemonics, private keys, or derivation inputs that are
  tracked as sensitive by the secret-hygiene checks.
- Tongo parity tests pin public-key outputs generated by the independent
  TypeScript derivation toolchain. This retains an automatic compatibility
  check without revealing private material on success or failure.
- Assertion diagnostics remain static so failures do not serialize derivation
  inputs into test output.

## Laws (tested)

1. The three supported Tongo derivation paths reproduce their checked-in
   TypeScript public-key vectors.
2. A parity assertion can expose only public values.
3. The test suite passes the repository's secret-hygiene check.

## Alternatives considered

- Keeping the diagnostics behind `--nocapture`: CI logs and user-invoked test
  runs can still retain the output.
- Replacing parity vectors with pairwise uniqueness assertions: that would not
  detect a deterministic but incompatible derivation implementation.
- Suppressing CodeQL: removes the signal without enforcing the desired test
  logging policy.

## Guardrail baseline

Removing the diagnostics shortens
`crates/client/tests/tongo_sepolia_integration.rs`; its file-size baseline
ratchets down from 1225 to 1201 lines. No baseline grows and no public API or
runtime behavior changes.
