# Krusty 0.14.0 release

Date: 2026-10-28. Status: accepted.

Release the security fixes merged since 0.13.0. Use a pre-1.0 minor version
because transactions signed without a `ResourceBoundsCeiling` now bid no
priority fee instead of the network median. That behavior change must not
flow to dependents still on `^0.13.0`.

All workspace packages inherit 0.14.0. Internal `krusty-kms-*` path
dependency requirements move from 0.13.0 to 0.14.0 so packaged crates
resolve the same release family. Pre-1.0 caret ranges on 0.13.0 exclude
0.14.0. Path dependencies without a version requirement (`krusty-kms-cabi`,
the experimental crates, and the excluded controller) stay unchanged.

The dated changelog entry is the former `## [Unreleased]` security notes:

- V3 `tip` pinning on every signed invoke and deploy-account transaction
  (#180).
- `rustls-webpki` 0.103.16 and `webpki-roots` / `webpki-root-certs` 1.0.10,
  clearing RUSTSEC-2026-0381, -0382, and -0383 (#180).
- `crypto-bigint` 0.7.10, `ctutils` 0.4.6, and `tokio` 1.54.1, clearing
  RUSTSEC-2026-0387, -0385, and -0386 (#184). Those two workspace floors
  move with the lockfile. The same lockfile also carries the `sha2` 0.11.1
  bump (#179).

No implementation or export changes occur in this release-preparation PR.

Package all eight publishable crates before merging. Tag only the merged
`main` commit as `v0.14.0`, then use the protected crates.io GitHub Actions
OIDC workflow. The npm workflow publishes `@starknetfoundation/krusty-kms-wasm`
0.14.0 on merge to `main`, because the WASM package takes the workspace
version and already-published versions are skipped. Keep the release tag
immutable; retry the same workflow for partial publication, or use a new
patch version for source fixes.
