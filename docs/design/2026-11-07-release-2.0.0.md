# Krusty 2.0.0 release

Date: 2026-11-07. Status: proposed.

## Why a major

Two days after 1.0.0, `## [Unreleased]` holds a breaking change: #214 makes
`krusty-kms-wasm` read unprefixed felt digits as decimal. On 1.0,
`isValidFelt` and `isValidStarkPrivateKey` documented unprefixed hex as valid
input, and most felt paths read `"1000"` as `0x1000`. Callers who relied on
that get different keys, addresses, hashes and signatures without an error
(`2026-11-07-wasm-decimal-felt-input.md`). Under the semver policy any
**Breaking** bullet requires a major. Shipping 1.1.0 instead would have meant
reverting #214.

`cargo-semver-checks` does not see #214, because no Rust or WASM signature
changes. The bump comes from the changelog marker, not from the lint.

## What else is included

- **`CachePolicy::max_entries` and `CachePolicy::new` removed.** They were
  deprecated in `[Unreleased]` with a promise of removal in 2.0.0
  (`2026-11-05-deprecate-cache-policy-max-entries.md`). The deprecation never
  shipped in a release, so 2.0.0 removes them directly. `with_ttl` is the only
  constructor.
- **Nostr raw-message signing (#215)** and **SNIP-12 starknet.js parity
  (#216)** change signatures for some inputs. Both are classed as security
  fixes, because the previous output did not meet the documented contract
  (BIP-340 raw message, SNIP-12 as implemented by starknet.js).
- **PSBT `SIGHASH_ALL` partial-signature refusal (#212)**, a security fix.

## Removal lands in this PR

Feature PRs run `cargo-semver-checks` with `--release-type minor`, so a
feature PR that removes a public field fails. Only a PR that changes the
workspace version is checked against the previous tag at its actual
increment. The `CachePolicy` removal therefore rides in this release PR,
checked against `v1.0.0` as a major. `AGENTS.md` and `docs/crates-release.md`
now say this for future majors.

## Oracle wire compatibility

The protocol version stays 1.0. `CachePolicy` serializes through a private
wire struct that still writes `"max_entries": 1`, so 1.0 gateways, which
require the field and reject `0`, accept 2.0 clients. Deserialization ignores
the field, so 2.0 gateways accept 1.x clients whether they send it, send `0`,
or omit it. A domain test pins both directions.

## Version and dependency ranges

Every workspace package inherits 2.0.0. All 25 internal `krusty-kms-*` path
dependency requirements move from `1.0.0` to `2.0.0`, since `^1.0.0`
excludes 2.0.0. Later 2.x minor and patch releases leave them alone.

## Publication

Package all eight publishable crates before merging. Tag only the merged
`main` commit as `v2.0.0`, then use the protected crates.io GitHub Actions
OIDC workflow. Merging also starts the npm publish of
`@starknetfoundation/krusty-kms-wasm` 2.0.0, gated by the `npm` environment.
Its release notes should lead with the felt-input change and the `0x` rule.
Keep the release tag immutable. A partial publication is retried by rerunning
the same workflow; a source fix gets a new patch version.
