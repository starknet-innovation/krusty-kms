# PQB WASM boundary

Expose the existing fixed-profile Rust PQB implementation to Bramble without
exporting seeds, child entropy, private keys or complete witness tables.
`WasmPqbVault` owns a Rust vault and its explicit network (`main`, `testnet4`,
`regtest`). Root derivation accepts an optional BIP39 passphrase and BIP85 index;
restoration accepts only the 24-word child phrase. No secret export is added.

Preparation consumes the full unsigned transaction, expected script hash, input
index and ordered 8/9 HORS plus three menu choices. `WasmPqbRequest` privately
retains the validated Rust request. Its public digest/sighash copies cannot alter
authorization. Both handles support idempotent `dispose()` and generated `free()`;
disposal drops Rust owners and preserves their zeroization. Calls on disposed
handles fail. No raw-digest signing operation or serialized request import exists.

Public results are plain objects containing lowercase unprefixed hex, in Rust's
canonical order. Secret disclosures copy only selected bytes to JavaScript via
wiped Rust hex buffers, then drop the zeroizing Rust disclosure. JS copies and
compiler/dependency copies cannot be reliably wiped. Inputs follow the existing
owned, immediately zeroized mnemonic/passphrase boundary policy. All numeric
arguments arrive un-narrowed and are checked as exact integers. Selection arrays
must be plain arrays and are length checked before reading elements. Transaction
hex, script hashes and PSBT base64 are length bounded before copying from JS. Deposit signing delegates to Rust's strict
PSBT owner/UTXO/SIGHASH_ALL checks, using the vault's retained network for addresses.

The caller must durably journal the exact request digest before authorization and
permanently reject any different digest for that vault, across concurrency,
restarts and restoration. Exact retries remain deterministic. The KMS does not
verify puzzle hits, funding, recipients, fees or Bitcoin consensus.

This is an additive npm API: propose 3.1.0 in a separate release PR following
`docs/crates-release.md`. Keep this implementation's workspace version at 3.0.0;
never replace the published package. No publication or release tag is authorized.
Tests exercise the built web package under Node and generated declarations, plus
WASM reference-vector tests and the existing export suite.
