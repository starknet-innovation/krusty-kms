# Krusty 3.0.0 release

Date: 2026-11-14. Status: proposed.

## Why a major

The Argent legacy correction changes deterministic private keys for valid inputs
whose intermediate Ethereum key has leading zero bytes. This affects
`derive_stark_from_eth_key`, `derive_argent_legacy_private_key`, the corresponding
WASM exports and ArgentLegacy discovery. Rust signatures staying the same does
not make a wallet derivation change compatible. Accounts created with Krusty
2.0.0 may require its old derivation for recovery, even though 3.0 now matches
Argent X. The [migration guide](../migration-3.0.md) describes that path.

The breaking behavior therefore requires 3.0.0 over the published 2.0.0; the
changelog labels it Breaking. Cargo's API semver checker cannot detect this
output change and is supplementary. The actual major increment is checked
against `v2.0.0`. No 2.1.0 release is being prepared or published.

## Included changes

- Fixed-profile PQB key management: BIP85 derivation/restoration, public locking
  scripts and grinder material, transaction-bound selective disclosure and legacy
  SIGHASH_ALL co-signing, and deposit PSBT signing. Python/TypeScript fixtures
  cover derivation, scripts, selected witnesses and signatures. PQB remains
  research code: callers maintain a durable exposure journal, validate funding,
  destinations, fees and puzzle solutions, and assemble/submit transactions.
  No real solve or on-chain spend was performed by this integration. This release
  adds no PQB FFI/WASM exports.
- Mnemonic entropy encoding, Nostr envelope metadata, signing/decryption
  hardening, range-proof validation, exact WASM integer validation with nullable
  TypeScript inputs preserved, and bounded gateway error retention.
- Secret-copy hardening and control-backed optimized native/WASM memory probes.
  These have compiler-dependent coverage, not a universal memory-erasure guarantee.
- Fixed optional QUIC dependency versions in the workspace lockfile.

## Internal dependencies

All versioned internal `krusty-kms-*` path requirements move to `3.0.0`, so a 3.0
consumer cannot silently select a 2.0 implementation. This also ensures the
gateway receives the domain's current bounded `GatewayError::new` behavior;
that is required even though the constructor's signature did not change.
The SDK's range validation and WASM's Nostr metadata calls likewise require the
new release. Path-only private C ABI/controller dependencies remain path-only.
Refresh the workspace and both standalone memory-probe lockfiles to 3.0.0.

## Publication

Package all eight publishable crates and run `tools/check.sh all`. Independently
review the whole updated release diff before pushing. Retain the stable-line
policy and migration links in README/SECURITY and update the release playbook's
current-major examples. The focused release PR only prepares the release.
Only a merged main commit may later be tagged `v3.0.0`; never move or recreate
that tag. Publication uses the protected crates.io OIDC workflow. Merge also
starts npm 3.0.0 publication, gated by the protected `npm` environment. Confirm
trusted publishers and obtain environment approvals before publishing. A partial
publication is retried through its existing run; source fixes need a new patch.
