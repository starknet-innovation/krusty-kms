# Krusty 4.0.0 release

Date: 2026-11-24. Status: proposed.

## Why a major

Three changes alter the behaviour of existing public entry points, and one
changes a public type. None changes key or address derivation.

- **KDF input bounds** (from #244, stacked on #241). Existing Rust and WASM
  encryption calls reject inputs that 3.x accepted: scrypt N above 2^18 for new
  direct encryption and default WASM decryption, non-16-byte direct salts,
  oversized plaintext and ciphertext, v3 work above N·r·p = 2^21, and numeric
  strings for WASM scrypt N. Signatures are unchanged, so
  `cargo-semver-checks` cannot see this; the changelog marks it Breaking. Older
  high-cost ciphertext stays recoverable through `decrypt_private_key` and
  `decryptPrivateKeyHighCost`. See [KDF input budgets](2026-11-13-kdf-input-budgets.md).
- **Tongo audit hints** (from #239). The shared serializer and C ABI emit
  different felts for identical inputs, and `AEBalance` gains fields. Earlier
  docs promised that encoder would not change. See
  [Tongo audit hint compatibility](2026-11-13-tongo-audit-hint-compatibility.md).
- **`async-nats` 0.53** (from #266). `NatsMultisigCoordinator::new` takes an
  `async_nats::Client`; 0.51 and 0.53 are semver-incompatible, so callers who
  pass their own client must upgrade it. `cargo-semver-checks` does not flag a
  dependency's version moving under a public type. The bump picks up 0.52's
  fix for a remotely triggerable header-value panic.

Those design notes were written while the line was 2.x and say the changes must
wait for a major; this is that major. The increment is checked against `v3.2.0`.

The scrypt scratch wiping from #241 is a non-breaking security fix that lands
here because #244 depends on it.

## Not included

`unicode-normalization` stays at 0.1.25 in the lockfile. Moving to Unicode 18
tables would change seeds for some passphrases and needs versioned derivation
and a recovery path, per [stable mnemonic normalization](2026-11-18-stable-mnemonic-normalization.md).
The published manifest range is unchanged.

## Internal dependencies

All versioned internal `krusty-kms-*` path requirements move to `4.0.0`, so a 4.0
consumer cannot silently select a 3.x implementation. That matters here: the
client's event decoder and the SDK's audit serializer must agree on the hint
layout, and the WASM crate relies on the bounded KDF entry points. Path-only
private C ABI/controller dependencies remain path-only. Refresh the workspace
and both standalone memory-probe lockfiles.

## Publication

Package all eight publishable crates and run `tools/check.sh all`. Independently
review the whole release diff before opening the PR. README, SECURITY and the
WASM README now name the 4.x line and link the
[4.0 migration guide](../migration-4.0.md); AGENTS.md and the release playbook use
4.x examples. Only a merged main commit may be tagged `v4.0.0`; never move or
recreate that tag. Publication uses the protected crates.io OIDC workflow.
Merging also starts npm 4.0.0 publication, gated by the protected `npm`
environment. A partial publication is retried through its existing run; source
fixes need a new patch.
