# WASM getters for Copy fields

Rust 1.99 Clippy reports `clone_on_copy` in wasm-bindgen getters generated by
struct-wide `getter_with_clone`. With warnings denied, this blocks unrelated PRs.

The affected structs now use ordinary copying getters for scalar fields and
field-level `getter_with_clone` for strings and nested points. Property names,
types, setters, and ownership semantics stay the same. No lint is suppressed.
The export snapshot records the more precise attributes; it does not introduce
new JavaScript properties or remove existing ones.

The file-size baselines grow only by the field attributes required for this fix:
`proof.rs` by 22 lines, WASM `types.rs` by 4, and mental-poker `types.rs` by 1.
Moving proof logic or types would add unrelated changes to a CI compatibility fix.

JavaScript boundary tests exercise scalar getters and setters, optional values,
and cloning getters for strings and nested points. Rust 1.99 lint-complexity is
also the regression check for the compilation failure.
