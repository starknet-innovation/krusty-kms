# Krusty 1.0.0 release

Date: 2026-11-05. Status: accepted.

First stable release of the published crates. 0.16.0 was released earlier
the same day instead of 1.0.0 (see `2026-11-05-release-0.16.0.md`), because
breaking changes that were already promised had not landed. After 1.0.0 each
of them would have needed 2.0.0. They have all landed now:

- `felt_to_u256_pair` removed (#205);
- JSON-RPC response bodies capped at 16 MiB through `BoundedHttpTransport`
  and `StarknetRpcClient`, changing the provider type across the client,
  wallet-api and gateway public APIs (audit M-2, #206);
- the remaining `#[deprecated]` APIs removed: `ArgentAccount::with_class_hash`
  and `decrypt_cipher_balance_with_default_limit` (#208).

The same range carries two fixes: audit-hint nonce restoration in Tongo
event parsing (#204) and empty `HexBytes` round-tripping (#207). #207 had no
changelog bullet; this PR adds one.

## Version and dependency ranges

Every workspace package inherits 1.0.0. All 25 internal `krusty-kms-*` path
dependency requirements move from 0.16.0 to 1.0.0, since `^0.16.0` excludes
1.0.0. From here on, a requirement of `1.0.0` covers every 1.x release, so
later minor and patch releases leave these requirements alone. Only the next
major version moves them again.

`cargo-semver-checks` failed on #205, #206 and #208 against the 0.16.0
baseline by design. Comparing this PR against `main` shows no API change. The
next PR's baseline is 1.0.0, so from now on the check is enforced against
the stable API.

## What 1.0.0 does not settle

- `CachePolicy::max_entries` (`krusty-kms-domain`) stays. Its docs call it
  deprecated and the gateway ignores it, but it is an oracle wire field.
  Removing it would be a protocol change, which needs 2.0.0 or a versioned
  wire format.
- `krusty-kms-controller`, `krusty-kms-oracle`, `krusty-kms-cabi` and the
  experimental crates are not published to crates.io. The stability promise
  covers the eight published crates and the npm WASM package.
- The controller still uses `JsonRpcClient<HttpTransport>`, its lockfile does
  not resolve, and CI does not audit it. That is left for separate work.

## Publication

No implementation or export changes occur in this release-preparation PR.
Package all eight publishable crates before merging. Tag only the merged
`main` commit as `v1.0.0`, then use the protected crates.io GitHub Actions
OIDC workflow. Merging also starts the npm publish of
`@starknetfoundation/krusty-kms-wasm` 1.0.0, gated by the `npm` environment.
Keep the release tag immutable. A partial publication is retried by
rerunning the same workflow; a source fix gets a new patch version.
