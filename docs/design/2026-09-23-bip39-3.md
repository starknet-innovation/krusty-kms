# BIP-39 3.0 dependency

Date: 2026-09-23. Status: accepted. Origin: Dependabot bump of `bip39` 2.2.2 to 3.0.0.

## Problem

`[workspace.dependencies]` pins `bip39` at `2.2.0` (locked at 2.2.2) with the
`zeroize` feature. 3.0.0 is a semver-major of the library that parses phrases,
encodes entropy, and derives seeds. The guardrail treats that manifest change
as a production-dependency change and requires this note.

## Interface we keep

Callers still go through the existing wrappers. No signature changes.

| Input | Output | Failure |
| --- | --- | --- |
| word count 12, 15, 18, 21, or 24 | English BIP-39 phrase | any other count → `KmsError::InvalidMnemonic` |
| phrase | unit, if checksum and wordlist accept it | `KmsError::InvalidMnemonic` |
| phrase + passphrase | 64-byte BIP-39 seed | invalid phrase → `KmsError::InvalidMnemonic` |
| entropy bytes (C ABI) | English phrase | bad length or entropy → `KMS_ERR_INVALID_INPUT` |

Generation still fills a `Zeroizing` entropy buffer from `rand::rngs::SysRng`
and calls `Mnemonic::from_entropy`. The parsed `Mnemonic` stays inside
`Zeroizing`, which is why the workspace dependency keeps `features = ["zeroize"]`.
OS-entropy failure still panics; that path is unchanged.

## Why 3.0.0 does not change that contract

The 3.0.0 changelog is four items. None of them are on the path above.

- `WordCount` and OS-RNG generation apply to `Mnemonic::generate` behind the
  optional `rand` feature. This workspace does not enable `rand`. Entropy stays
  in `generate_mnemonic`.
- The `rand` crate floor moved from 0.6 to 0.7 on that same optional feature.
  It is not in this crate's dependency closure.
- Multilingual prefix lookup deprecates an incomplete slice API. Krusty parses
  full English phrases only (the default wordlist) and does not call prefix
  lookup.
- Ambiguous-language entropy and serde round trips matter when a phrase is
  valid in more than one enabled wordlist. Only English is enabled, and
  `Mnemonic` is not serialized.

`from_entropy`, `FromStr`, `to_seed`, and `Zeroize` keep the shapes these crates
already call. `to_seed` remains available through the default `std` feature
(`unicode-normalization`). Seed bytes stay BIP-39 PBKDF2-HMAC-SHA512.

## Laws

Existing tests are the check, not a new suite:

- `mnemonic_seed_release_vectors_match` pins phrase + passphrase → seed.
- `generate_mnemonic` / `validate_mnemonic` tests pin word counts and rejection
  of a bad phrase.
- The C ABI still rejects entropy longer than `KMS_MAX_ENTROPY_LEN` before
  `from_entropy`.

## Lockfile side effect

Regenerating the lockfile retargets dev-transitive `tempfile` 3.25.0 from
`getrandom` 0.3.4 to 0.4.3. That crate allows `>=0.3, <0.5`, and 0.4.3 was
already in the lockfile for other crates. `tempfile` is not on the mnemonic or
signing path.

## Alternative

Staying on 2.2.2 avoids the major bump and leaves the same call sites. It also
leaves the workspace on a line 3.0.0 supersedes, and Dependabot will reopen the
bump. Switching generation to `Mnemonic::generate` would hide the entropy buffer
inside `bip39` and drop the explicit `Zeroizing` fill. Rejected.
