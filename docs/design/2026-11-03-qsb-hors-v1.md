# QSB-HORS-v1 vault secrets

## Problem

A Quantum Safe Bitcoin (QSB) vault is a Bitcoin output locked by 2 × 150
one-time HORS secrets of 20 bytes each; the script commits to
`HASH160(secret)`. A withdrawal reveals 8 round-0 and 7 round-1 preimages. The
draft BIP "QSB Wallet Secret Management"
(<https://github.com/adrienlacombe/bips/blob/bip/qsb-wallet-secret-management/bip-qsb-wallet-secrets.md>,
profile `QSB-HORS-v1`) makes these secrets deterministic: `K` is the
SLIP-0021 child `"QSB-HORS"` of the BIP-39 seed, and each secret is a
truncated `HMAC-SHA256(K, tuple)`.

A wallet that holds the QSB phrase needs commitments to build a deposit, a
digest that binds a disclosure to its spending transaction, and the selected
preimages. Krusty is the component allowed to derive keys and release
secrets, so it provides these as stateless primitives. The BIP's disclosure
journal stays with the wallet, which records `exposed` before it asks for
preimages.

## Contract

`krusty_kms::qsb_hors` (re-exported at the crate root):

- `QsbVault::new(net, v)` accepts only `net ∈ {0x00, 0x01}` and `v < 2^31`.
- `QsbRevealIndices::new(round0, round1)` accepts exactly 8 and 7 indices,
  each in `[0, 149]` and distinct within its round, and keeps their order.
- `derive_qsb_commitments(mnemonic, vault, passphrase)` returns
  `c[v][0][0..150]`, `c[v][1][0..150]`, and `R[v]`.
- `qsb_reveal_digest(T, indices)` parses `T` and returns
  `B = SHA256(T)` and `D = SHA256("QSB-HORS-v1/reveal" || I || B)`.
- `reveal_qsb_preimages(mnemonic, vault, indices, passphrase)` returns the 15
  named secrets, round 0's then round 1's, in request order. `QsbPreimages`
  wipes on drop and redacts `Debug`.

The seed is Krusty's existing `mnemonic_to_seed` (BIP-39, NFKD, optional
passphrase). `K`, the seed, and full secret sets live in a private submodule
and have no public path. Invalid parameters are `InvalidDerivationPath`;
an invalid `T` is `DeserializationError`.

WASM exports `deriveQsbCommitments(mnemonic, net, vault_index, passphrase?)`,
`qsbRevealDigest(transaction_hex, round0, round1)`, and
`revealQsbPreimages(mnemonic, net, vault_index, round0, round1, passphrase?)`.
Numbers arrive as `JsValue` and are deserialized as exact integers, because
the `u8`/`u16`/`u32` ABI conversions wrap (`256 → 0`, `2^32 + 7 → 7`) and
would select another namespace, vault, or secret. Parameter-level
`unchecked_param_type` keeps the TypeScript types `number` and `number[]`.
Transaction hex must be lowercase without a prefix. The preimage strings are
hex-encoded into a wiped stack buffer, so no unwiped copy stays in linear
memory; the JS strings themselves cannot be wiped.

## Transaction parsing

`T` must be a complete legacy serialization: canonical CompactSizes, every
scriptSig empty, no segwit marker or witness, no trailing bytes. Because only
the exact recorded `T` may be retried after exposure, disclosing for a `T`
that can never confirm strands the vault. The parser therefore also applies
Bitcoin's context-free `CheckTransaction` rules: at least one input and one
output, no duplicate or null outpoints, each output and the total within
`MAX_MONEY`, and at most 1,000,000 bytes. No valid transaction fails them.
It does not check that `T` spends the vault, verify the QSB puzzle, or check
the link between `T` and the indices; the wallet must disclose that trust
boundary as the BIP requires.

## Laws

1. Every revealed preimage hashes to the commitment at its `(round, index)`.
2. `reveal` output order is request order; reordering indices changes `D`.
3. `D` is a function of `(I, T)` only; `B` is never caller-supplied.
4. No input outside the profile reaches derivation: the validated types cannot
   hold it, and the WASM layer validates numbers before reading the mnemonic.

## Tests

The BIP's `vectors.json` is copied verbatim into
`crates/kms/tests/fixtures/qsb_hors_v1_vectors.json`. Unit tests check its
`K`-based vectors (seed to `K`, secrets, commitments, roots, digest) through
the private key type, plus the SLIP-0021 reference vector. Integration tests
check mnemonic-level values generated with the BIP's `reference.py`
(including a 24-word phrase, a passphrase, NFKD, both namespaces, and
`v = 2^31 - 1`) and each refusal. The derivation matches the QSB Ledger
app's `qsb-core/src/hors.rs`, which the BIP cites as its derivation reference.

## Surface and dependencies

- New dependency: `ripemd` 0.2.0 (RustCrypto, MIT/Apache-2.0, on the same
  `digest` 0.11 as `sha2`) for `HASH160`. It adds no other crate.
- `crates/wasm/src/lib.rs` grows by one line (`pub mod qsb_hors;`); its
  file-size baseline moves from 400 to 401.
- The WASM export extractor attributed a parameter's `#[wasm_bindgen(...)]`
  to the next export. It now leaves parameter attributes in their own
  signature, with a self-check. No existing snapshot entry changes.
