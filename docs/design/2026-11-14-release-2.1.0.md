# Krusty 2.1.0 release

Date: 2026-11-14. Status: proposed.

## Why a minor

The pending changes add public APIs: PQB vault primitives, mnemonic encoding from
entropy, Nostr envelope metadata and range-proof width validation. They require a
minor increment over the published 2.0.0. The changelog has no removals or marked
breaking changes; existing function signatures remain compatible. The release
semver check compares the complete release against `v2.0.0` at the actual bump.

## Included changes

- Fixed-profile PQB key management: BIP85 derivation/restoration, public locking
  scripts and grinder material, transaction-bound selective disclosure and legacy
  SIGHASH_ALL co-signing, and deposit PSBT signing. Python/TypeScript fixtures
  cover derivation, scripts, selected witnesses and signatures. PQB is research
  code, not an audited construction or a complete wallet: the caller maintains
  the durable exposure journal, verifies funding/destinations/fees and puzzle
  solutions, and assembles/submits transactions. No real solve or on-chain spend
  was performed by this integration. This release adds no PQB FFI/WASM exports.
- Mnemonic entropy encoding and failure handling, secret-copy and optimized
  native/WASM memory hardening, and stricter range-proof input validation.
- Nostr envelope ids/timestamps for replay handling, signing verification and
  decryption error/key-buffer hardening.
- Exact WASM integer validation with nullable TypeScript inputs preserved;
  bounded gateway errors and corrected Argent legacy derivation with leading
  zero bytes. The latter corrects previously wrong derived keys for affected
  phrases, as documented in the changelog.
- Fixed optional QUIC dependency versions in the workspace lockfile.

## Internal dependency lower bounds

Most internal requirements remain `2.0.0`: `^2.0.0` admits 2.1.0. Two consumers
use APIs first added in this release, so their requirements must move:

- `krusty-kms-sdk` requires `krusty-kms-crypto` >=2.1.0 for
  `range::validate_bit_size` in transfer and withdrawal validation.
- `krusty-kms-wasm` requires `krusty-kms` >=2.1.0 for
  `open_nostr_application_data_with_metadata`.

The private C ABI crate uses a path-only KMS dependency, so no registry version
range needs changing for its new mnemonic entropy encoder. Refresh the workspace
and both standalone memory-probe lockfiles to the inherited 2.1.0 versions.

## Publication

Package all eight publishable crates and run `tools/check.sh all` before opening
the focused release PR. An independent agent reviews the entire release diff
before that PR is opened. Only the merged main commit may be tagged `v2.1.0`;
never move or recreate that tag. Publishing uses the protected `crates-io` GitHub
Actions OIDC workflow. Merge also starts the npm 2.1.0 publication for
`@starknetfoundation/krusty-kms-wasm`, protected by the `npm` environment.
Keep the research/integration limitations in the release notes. Retry a partial
publication through its existing workflow; a source fix needs a new patch release.
