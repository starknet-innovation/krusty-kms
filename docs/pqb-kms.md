# PQB KMS integration

`krusty_kms::pqb` implements the fixed, real-puzzle `PQB` profile from
fireblocks-labs/pqb commit `eccdd09772edf14ab37fc63992b0626ad7ff2221`.
It is separate from `qsb_hors`; their seeds, tables and disclosure rules differ.
PQB remains a research construction. These primitives do not establish its security.

## Derive and fund

Construct `PqbVault` with `from_mnemonic(wallet_words, passphrase, index, network)`.
This derives BIP85 at `m/83696968'/39'/0'/24'/index'`, then binds the child entropy
to `pqb/vault-seed|hybrid|PQB|real|<network>`. Use each child for at most one vault.
`PqbNetwork` distinguishes mainnet, testnet4 and regtest.

`from_child_mnemonic` restores the **24 BIP85 child words**, without treating them
as a wallet root. `from_child_entropy` and `from_seed` support existing vaults;
callers must wipe the source buffers they supplied. Electrum and xprv parsing are
not part of this module.

`public_material()` returns the exact 4,908-byte locking script and its SHA256,
109 HORS commitments, the co-signing public key, and public menu recovery points
for a grinder. No seed, private key, full secret table or menu scalar is returned.
Menu points follow the reference's `(add_n, odd)` variant order. The material
can be used without passing a secret seed to `@pqb/core`'s `buildLock`.

`deposit(network)` returns a P2WPKH address and public key. To sweep, construct a
version-0 PSBT with matching `witness_utxo` and full `non_witness_utxo`, and call
`sign_deposit_psbt(psbt_base64, input_indices)`. Only this vault's deposit inputs
and SIGHASH_ALL are signed. It uses ordinary RFC6979 low-S signatures, matching
PQB rather than Krusty's existing low-R Bitcoin signer. It does not finalize or
broadcast the PSBT.

## Authorize a withdrawal

1. Verify the funding output, destinations, fee, pinning nonce and grind results.
   Build the final unsigned legacy transaction with every scriptSig empty.
2. Construct `PqbSelection::new(round0, round1, menus)`. The 8 and 9 HORS indices
   must be distinct across both rounds and below 109. The three menu picks must
   be below 12, 16 and 16. Order is preserved.
3. Call `prepare_disclosure(transaction, input_index, expected_lock_hash, selection)`.
   The expected hash must identify the vault being spent. The request exposes
   its co-signature sighash, three stage sighashes and a journal digest.
4. **Durably record the digest as exposed before calling `authorize(&request)`.**
   Permanently reject a different digest for that vault, including after crash,
   concurrent requests or restore. An exact retry is deterministic.
5. `authorize` returns only the selected 20-byte round-0 preimages, selected
   32-byte round-1 preimages, three selected menu signatures and the full-lock
   co-signature. Use these to assemble the scriptSig outside the KMS.

The journal digest is SHA256 of the concatenation of
`"krusty/pqb/disclosure/v1\0"`, the 32-byte script hash, the input index as an
8-byte big-endian integer, the 8 round-0 indices, the 9 round-1 indices, the
3 menu indices (each index is one byte), and the unsigned transaction bytes.
This is Krusty's journal format; it does not change PQB's on-chain format.

The request validates canonical transaction structure, context-free outpoint and
amount rules, input bounds and lock ownership. The co-signature always covers the
whole generated lock and the exact transaction using legacy SIGHASH_ALL.
There is no public raw-digest signing or arbitrary-label derivation operation.

The KMS does **not** execute Bitcoin Script, verify puzzle hits, authenticate the
funding amount, approve recipients or maintain a durable journal. Merely computing
a digest does not prevent reuse. The caller's journal and validation are required
parts of the integration. Reconstructing `PqbVault` does not restore exposure state.
Seed owners and disclosures redact Debug and do not implement Clone or Serialize;
the disclosure buffers wipe on drop. See the module's memory documentation for
compiler and hashing limitations.

## Reference checks

`cargo test -p krusty-kms --lib pqb` runs offline against committed public fixtures.
The fixtures cover three real scripts, three assembled spends, public grinder
points, BIP85 derivation/restoration/network binding, deposit addresses and PSBT
signatures. The spends are assembly vectors, not completed puzzle solves.

Regenerate from the local Python reference (requires its pinned `coincurve`):

```sh
python3 tools/pqb-kms-vectors.py /path/to/pqb > crates/kms/tests/fixtures/pqb_kms_vectors.json
npm ci --prefix /path/to/pqb/js
npm test --prefix /path/to/pqb/js
node tools/verify-pqb-kms-vectors.mjs /path/to/pqb
```

The exporter records the reference commit and source-vector SHA256. The extra
wallet/deposit cases are generated by Python and also checked by the TypeScript
verifier. All fixture seeds are public test values that have never held funds.
The port's upstream MIT notice is included in `crates/kms/licenses/PQB-MIT.txt`.
